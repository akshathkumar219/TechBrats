# Model Bake-Off — Harness & Selection Protocol

**Purpose:** decide which local model ships inside SyndicateBrain, empirically, with a number you can put on a slide.

**When this runs:** the *harness and fixtures* are built in Phase 0, alongside the synthetic dataset — they cost nothing and need no model. The *bake-off itself* runs at the start of Phase 4, when you swap the stubbed extractor for a real one. Until then the app is built against `stub_extractor.py`, which returns the fixtures' expected output verbatim.

**Why build the harness before you need it:** the fixtures are the same artefact as your golden-file regression tests. Write them once in Phase 0 and they (a) let you build the whole pipeline with zero model latency, (b) pick your model in Phase 4, and (c) catch regressions every time you change a prompt afterwards. One piece of work, three jobs.

---

## 1. What Is Actually Being Tested

Not "which model is smarter." One narrow question:

> Given a code-mixed Hindi/English FIR page, which model most reliably returns valid JSON containing the right entities, with the right spans, without inventing anything?

Everything else — reasoning ability, coding, benchmarks, parameter count — is irrelevant to this decision.

---

## 2. Fixture Spec

**Location:** `data/fixtures/`

```
data/fixtures/
├── fir_001.txt        ← the input text (code-mixed, as it would come off OCR)
├── fir_001.json       ← hand-written expected extraction
├── fir_002.txt / .json
├── ...
└── README.md          ← what each fixture is designed to break
```

**Build 6 fixtures, each targeting a specific failure mode:**

| # | Designed to test | What it contains |
| :-- | :--- | :--- |
| `fir_001` | Baseline | Clean code-mixed FIR, 3 accused, 2 phones, 1 vehicle. Everything unambiguous. |
| `fir_002` | **Alias preservation** | `विक्रम सिंह उर्फ विक्की` and later just `विक्की`. Model must extract both surface forms and must **not** silently expand `विक्की` → `Vikram Singh`. |
| `fir_003` | **Partial names** | `मो. कलाम`, `Md. Kalam`, `कलाम s/o स्व. अब्दुल`. Model must extract as-is, not complete them. |
| `fir_004` | **Script mixing** | Devanagari narrative, Latin-script phone numbers, IPC/BNS section refs in digits, an English-language annexure paragraph. |
| `fir_005` | **Negation & hearsay** | Contains "आरोपी ने कहा कि X वहाँ नहीं था" and a witness reporting what someone else claimed. Model must not extract a hearsay claim as a fact, and must not invert a negation. |
| `fir_006` | **Noise / bad OCR** | Deliberately corrupted characters, broken line wraps, a duplicated paragraph. Tests graceful degradation vs confident garbage. |

**Fixture text must be genuinely code-mixed.** Real Haryana FIRs interleave Devanagari narrative with Latin names, digits, and section references. A clean all-Devanagari test set will flatter every model and teach you nothing.

**Expected JSON is hand-written by a human.** Not generated by a model. This is the whole point — if the ground truth came from an LLM you are measuring agreement, not accuracy.

---

## 3. Scoring

Five metrics. Report all five; do not collapse them into one score.

| Metric | Definition | Why it matters here |
| :--- | :--- | :--- |
| **JSON validity rate** | % of calls returning schema-valid JSON on the first attempt | A model that needs constant retries is unusable in a batch pipeline. **Hard gate: below 95% is disqualifying regardless of everything else.** |
| **Entity recall** | found ÷ expected | Missing a suspect means missing a node in the graph |
| **Entity precision** | correct ÷ found | A hallucinated entity is a fake person in a criminal network. Weight this heavier than recall. |
| **Alias fidelity** | % of aliases where `surface` is preserved verbatim and *not* expanded | The single most important metric. A model that "helpfully" completes names destroys the resolution stage. |
| **Span accuracy** | % of entities whose char offsets land within ±5 chars of truth | Broken spans mean broken provenance, which means broken certificates |

Also record, but don't score on: mean latency per chunk, peak RSS, tokens/sec. These decide the 8 GB vs 16 GB tier, not the model choice.

## 4. Candidates

Run all of these. Add any that look relevant when you actually run it — verify sizes and language support on the official model cards at that time; this list is from Sept 2026 and this landscape moves monthly.

| Candidate | Why it's in |
| :--- | :--- |
| **Qwen3.5-4B-Instruct** Q4 | Current default for the 8 GB tier |
| **Qwen3.5-9B-Instruct** Q4 | Current default for the 16 GB tier |
| **Qwen3.5-2B-Instruct** Q4 | Floor test — if 2B passes, your minimum spec drops and that's a real pitch advantage |
| **Gemma 4 E4B** Q4 | Cleaner structured output; test whether that outweighs weaker Devanagari |
| **One Indic-tuned model** (Sarvam / AI4Bharat) | If JSON-mode reliability holds up. May win on Hindi and lose on the validity gate — find out. |

**Run every candidate with thinking/reasoning mode OFF.** Qwen 3.x reasoning traces leak into JSON output and will tank the validity rate for reasons that have nothing to do with extraction quality.

## 5. Harness

`brain/bakeoff/run.py`

```python
# Pseudocode — the shape, not the implementation.

CANDIDATES = ["qwen3.5:4b", "qwen3.5:9b", "qwen3.5:2b", "gemma4:e4b", "<indic>"]
FIXTURES   = sorted(Path("data/fixtures").glob("*.txt"))

for model in CANDIDATES:
    warmup(model)                          # never time a cold model
    for fixture in FIXTURES:
        text     = fixture.read_text()
        expected = json.loads(fixture.with_suffix(".json").read_text())

        for trial in range(3):             # 3 runs — measure variance, not one lucky sample
            t0  = time.perf_counter()
            raw = ollama_generate(model, EXTRACTOR_PROMPT.format(text=text),
                                  format="json", temperature=0, think=False)
            dt  = time.perf_counter() - t0

            valid, parsed, err = validate(raw, ExtractorSchema)
            record(model, fixture, trial, dt, valid, err,
                   **(score(parsed, expected) if valid else {}))

write_report("bakeoff_results.md")         # per-model table + per-fixture breakdown
```

**Scoring functions** (`brain/bakeoff/score.py`):
- `entity_match(found, expected)` — match on `(type, normalized)`; case- and whitespace-insensitive; Devanagari NFC-normalised before comparison.
- `alias_fidelity(found, expected)` — for every expected alias, assert its `surface` appears verbatim in output **and** assert no expected-partial name was expanded to its full form. The second half is the test that actually catches the dangerous failure.
- `span_ok(found, expected)` — `abs(found.start - expected.start) <= 5 and abs(found.end - expected.end) <= 5`.

**Output:** `bakeoff_results.md` — one table per model, one row per fixture, plus a summary table. Commit it. It is deck material and it is your justification when a judge asks "why this model?"

## 6. Decision Rule

Apply in order. Stop at the first candidate that survives.

1. **Gate:** JSON validity ≥ 95%. Fail → eliminated, no exceptions.
2. **Gate:** alias fidelity ≥ 90%. Fail → eliminated. This is the wrongful-merge risk and it is not negotiable.
3. **Gate:** fits the target tier — ≤ ~2.5 GB for the 8 GB laptop, ≤ ~6 GB for 16 GB.
4. **Rank survivors** by entity precision, then recall, then span accuracy.
5. **Tiebreak** on latency.

Ship the winner as default. Ship the best 8 GB-tier survivor as the low-RAM fallback. Record both in `.syndicate/models.json`.

---

## 7. Reusing the Fixtures Afterwards

Once the model is chosen, the same fixtures become the regression suite:

- `pytest brain/tests/test_extractor.py` runs all 6 fixtures against the chosen model and asserts the Phase-4 scores as floors.
- Any prompt edit that drops a score below its floor fails CI. Prompt changes look harmless and routinely aren't; this is the only thing that catches it.
- Re-run the full bake-off if you change model generation.

## 8. Working Without Models Until Phase 4

`brain/extract/stub.py`:

```python
def extract(doc_id, chunk_text, **kw):
    """Phase 0-3 stand-in. Returns the hand-written fixture output for known
    fixtures; raises loudly for anything else so you never silently build
    against fake data."""
    key = fixture_key(chunk_text)
    if key is None:
        raise StubMiss(f"No fixture for this chunk. Add one or wire the real extractor.")
    return json.loads(Path(f"data/fixtures/{key}.json").read_text())
```

Swap-in point is a single config flag: `BRAIN_EXTRACTOR = stub | ollama`. Everything downstream — resolution, graph, agents, certificate — is built and tested against the stub, at zero latency, before any model exists. When Phase 4 arrives you flip the flag and the only thing that changes is where the JSON comes from.

**This is the sequencing that makes "AI last" safe:** the pipeline never depends on the model working, so a bad model day never blocks the build.
